## 3. Root Cause Investigation — Where We Left Off

### 3.1 Code Paths

**Output head for single-token decode** (ds4.c ~L24004 `metal_graph_encode_output_head`):
- Branch `g->cuda_tp_ep && g->cuda_tp_output` → calls
  `metal_graph_output_logits_head_matmul` (ds4.c ~L24394) with `n_tokens=1`.

**Inside `metal_graph_output_logits_head_matmul`** (ds4.c L24462-24533):
If `tp_ok` is true (4-way), for each tier `t` in `tp_tiers[]`:
1. Copy `output_norm` → `batch_ffn_norm_by_tier[t]` via `ds4_gpu_tensor_copy_xdev`
2. `ds4_gpu_set_current_device(t)` then `ds4_gpu_matmul_q8_0_tensor(shard_out[t], ...)`
3. After all 4 shards: `ds4_gpu_set_current_device(home_tier=1)`
4. Gather shards back to `dst_logits` via `ds4_gpu_tensor_copy_xdev` × 4
5. `ds4_gpu_argmax_tensor` on home_tier=1

**TP tier ordering** (with head_tier=1, n_gpus=4, half=2):
`tp_tiers = [1, 3, 2, 0]`  (from `metal_graph_cuda_tp_output_tiers_for_head`, ds4.c L71)
- Shard 0 → tier 1 (vocab rows `[0, V/4)`)
- Shard 1 → tier 3 (vocab rows `[V/4, V/2)`)
- Shard 2 → tier 2 (vocab rows `[V/2, 3V/4)`)
- Shard 3 → tier 0 (vocab rows `[3V/4, V)`)

### 3.3 Likely Root Causes (NOT YET Verified)

**Candidate A — `ds4_gpu_matmul_q8_0_tensor` silent size guard failure**

`rocm/ds4_rocm_matmul.cuh` L236-239:
```c
weight_bytes > model_size - weight_offset  // returns 0 silently
```
For shards at high offsets (tiers 3, 2, 0), `weight_offset` is
`abs_offset + (V/4 * row_bytes)`, `(V/2 * row_bytes)`, `(3V/4 * row_bytes)`.
If this overflows or exceeds `model_size`, those shard `shard_out` tensors remain
**all-zero**. The gather copies zeros into the upper vocab region of `dst_logits`.
Argmax then picks the highest logit in tier 1's shard (rows 0..V/4), which if
random/garbage is the BOS token.

**Action**: Add fprintf before the guard check (see §4 below).

**Candidate B — HC state not reduced across all 4 tiers before output head**

In 4-GPU TP, layers 0-20 run on tier 0 ↔ tier 2 (attention TP pair), and layers
21-42 run on tier 1 ↔ tier 3. The MoE down-projection outputs from tiers 0 and 2
contribute to the HC residual. The output head is only on tier 1. For the output norm
to be correct, the HC state on tier 1 must incorporate contributions from **all 4
tiers**. If the MoE allreduce only covers the direct (home, partner) pair without
cross-pair accumulation (0→1 or 2→3), the output norm will be wrong.

**Action**: Check `ds4_rocm_xdev_accumulate_f32` calls around the end of the MoE
layer. Also check `ds4_gpu_tensor_copy_xdev_ordered` usage in `ds4.c` around
L23050-23200 (MoE output reduction).

**Candidate C — `tp_ok` guard silently rejecting the TP path**

`ds4.c` L24449-24460: if `logits_by_tier[t]` is too small for any tier, `tp_ok=false`
and `ok=false` is returned, causing a silent failure in the output head. The first
token is then whatever junk is in `dst_logits` from a previous decode step.

**Action**: Add fprintf after the `tp_ok` check (see §4 below).
